Task: PR-1922 - raise num_ctx from 2048 to 8192 in the local model definition (owner decision, 2026-10-09).

Repository: pib-backend. Ticket: PR-1922 (Jira). Make the change on a branch named PR-1922, created from origin/develop.

=== Why ===
The 2048 cap was justified as protection for the 4 GiB rig, but the 4 GiB variants never install the local
model: setup-pib.sh installs Ollama only for pib5edu, pib5advanced and pib5museum and logs a skip line and
returns success for everything else (see the case statement around line 1488). So num_ctx only ever applies
on 8 GiB devices.

Measured on 192.168.1.172 (8 GiB Pi 5), identical 863-token prompt, derived test models, removed afterwards:

    num_ctx   prefill   total    eval_count   loaded size
    2048      0.2 s     7.7 s    30           ~1.0 GB
    4096      0.3 s     5.7 s    22           1.30 GB
    8192      0.3 s     6.2 s    23           1.49 GB
    16384     0.2 s     6.1 s    24           1.73 GB

Prefill does not depend on num_ctx - it depends on the actual prompt length (~0.35 s per 1000 prompt tokens).
Memory grows ~55 MB per 1024 tokens. The device has 4.4 GB free, so 8192 is comfortable. This is evidence from
the ticket (comments 15149 and the decision comment); do not re-measure on a device.
