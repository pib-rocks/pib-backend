## IMPORTANT context (verified — read before changing anything)
A `save_current_pose` block ALREADY EXISTS (added by PR-1658) and already records the current pose under a
name. The REMAINING gap versus PR-1640 is the INPUT TYPE of the name:

- Current block (`program-blocks/pose-block.ts`, in `poseBlocks`):
      type: "save_current_pose", message0: "Save current pose as %1",
      args0: [{ type: "field_input", name: "NAME", text: "pose name" }]
  i.e. a FIXED text field on the block.
- Current generator (`program-generators/pose-generator.ts`, `save_current_pose`):
      return `${functionName}(${quotedField(block, generator, "NAME")})\n`;
  i.e. it emits a hardcoded string literal.

PR-1640 requires: "The name of the new pose should be defined through a STRING-INPUT ON THE RIGHT SIDE of the
block, so that it can also be set programmatically."
Acceptance criterion: "A user can record the current pose under a name which is given as a STRING OR VARIABLE
on the right side of the block."

So the change is: make the name a VALUE INPUT (right side) instead of a fixed field.
