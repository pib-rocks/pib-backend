## Goal
Add depth/stereo ROS2 interfaces to the pib camera node, following the verified persistent-pipeline pattern.
Depth data must come from the SAME one pipeline (per the OAK-D-Lite 1-pipeline constraint in the ticket/Confluence).

## Verified baseline (this repo)
- `ros_packages/camera/oak_d_lite/stereo.py`: CameraNode.init_pipeline() calls dai.Pipeline.start() once at node init (persistent connection). A 10 Hz timer_callback polls queue.tryGet() -> self.current_frame; get_camera_image reads cached frame on demand (no per-call connection). Publishing gated by get_subscription_count(). Pattern: persistent pipeline + cache + on-demand read.
- `ros_packages/datatypes/srv/GetCameraImage.srv` is `---\nstring image_base64` (empty request).

## Scope for THIS delegation (camera backend)
1. Extend the depthai pipeline to also produce Stereo/Depth outputs (ONE pipeline start, Color + Stereo outputs). Follow depthai v3 API conventions used in stereo.py (dai.node.Camera, requestIspOutput/createOutputQueue).
2. Cache current_depth alongside current_frame in the pipeline timer path.
3. Add new SRV type(s) under ros_packages/datatypes/srv:
   - GetDepthFrame.srv (return depth in a sensible encodable form, e.g. metadata + base64/numpy-compatible buffer), and
   - GetDistanceAtPx.srv (request int32 x, int32 y -> float32 distance_mm), and optionally
   - a publisher topic for depth (stereo_depth) gated on subscriber count like camera_topic.
4. Register the new services in CameraNode (create_service for get_depth_frame + get_distance_at_px).
5. Keep persistent connection: do NOT open a new pipeline per request; services read the cached current_depth.
